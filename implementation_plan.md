# Vial Armed 2.0: переписать на C++20 / Qt 6

## Выбор стека

**C++20 + Qt 6 Widgets.** Альтернатив лучше нет:
- Текущий код — PyQt5. Классы, сигналы, QPainter-отрисовка, QSettings, QProcess переносятся почти один в один: это порт, а не новый дизайн.
- Rust + Slint/egui дали бы ту же скорость, но всё пришлось бы проектировать заново (виджет клавиатуры, редактор HUD, канвас), и сроки выросли бы в разы.
- Qt Quick/QML — красивее анимации, но тяжелее старт и память, а 90 % UI тут — плотные формы и свой QPainter.

Зависимости: Qt 6 (Widgets, Gui, Svg, Network, Concurrent), hidapi (C, hidraw-бэкенд на Linux — без отцепления драйвера, как у нынешнего libusb), liblzma (определение клавиатуры Vial). Сборка — CMake.

## Честно о скорости

- **Задержки радио не исчезнут.** Через донгл один запрос ≈ 10–40 мс, это физика тоннеля `81/91` и одного слота в прошивке. Полная загрузка по 2.4G (8.6 с) упрётся в то же самое.
- **Что реально ускорится:** старт (сейчас Python + PyQt импорт ≈ 1–2 с → цель < 300 мс до окна), отрисовка HUD-превью, превью эффектов и тем, кодирование анимации экрана (сейчас чистый Python, в C++ в десятки раз быстрее), отклик UI.
- **Главная победа по ощущениям:** весь обмен с клавиатурой уходит в отдельный поток. Сейчас запросы идут из GUI-потока (опрос HUD каждые 150 мс, загрузка, сохранение) — отсюда «зависания». В 2.0 окно не замирает никогда.

## Стратегия

- Новое дерево `app/` в этом же репозитории, Python-версия живёт рядом до паритета. Релиз 2.0.0 — когда всё из списка ниже работает, затем Python удаляется.
- Перед удалением Python-рендерера HUD снимаем с него эталонные картинки (golden-тесты): C++-рендер обязан совпасть побайтно.
- Таблицы кейкодов (v5/v6, ~2 тыс. строк) не переписываются руками — генерируются скриптом из нынешних Python-таблиц в `constexpr`-массивы.

## Что теряем (нужно твоё «да»)

1. **Синхронизация с upstream vial-gui** станет ручной: их Python-изменения придётся портировать, а не мёржить.
2. **Веб-сборка (emscripten, `webmain.py`)** — выпадает.
3. Минимальные ОС у Qt 6: Windows 10+, macOS 11+, Linux уровня Ubuntu 22.04.

## Фазы

### 1. Каркас [NEW]
- `app/CMakeLists.txt`, `app/src/main.cpp`; версия из git-тега (замена `util/set_version.py`).
- CI: Linux (AppImage через linuxdeploy + .deb), Windows (MSVC, windeployqt, NSIS), macOS (dmg). Имена файлов `vial-armed-<ver>-*` как сейчас.
- Режимы запуска: окно, `--agent` (headless), `--linux-recorder`.

### 2. Транспорт и протоколы [NEW], без UI
- `HidTransport`: hidapi, отдельный `QThread`, очередь запросов с приоритетами (интерактив > опрос > фон), сигналы с результатом. Логика донгла переносится как есть: сброс устаревших ответов, растущий таймаут 150→600 мс.
- Обнаружение устройств: USB (Vial serial) + донгл `0c45:fefe` с пробой. Горячее подключение по событиям (udev через `QSocketNotifier` на Linux, `WM_DEVICECHANGE` на Windows) вместо опроса раз в N секунд.
- `VialProtocol` (= `keyboard_comm.py`): определение (LZMA), keymap пачками, энкодеры, макросы, tap dance, combos, key overrides, alt repeat, QMK settings, unlock.
- `ArmedProtocol` (= `qmk_armed.py`): всё, включая HUD, экран, кэш списков на диске.
- Загрузчик Vial (`firmware_flasher.py`).

### 3. Модели данных [NEW]
- Кейкоды (сгенерированные таблицы), KLE-парсер, раскладки (`keymaps.py`).
- Выражения в «Any keycode»: свой маленький парсер вместо `simpleeval`.
- `HudLayout` pack/unpack, `HudRenderer` (QFF-шрифты, RLE — помнить: неповторяющийся отрезок `c-127`), пресеты.
- `LightingTheme`, рендер тем и превью эффектов.
- `ScreenMedia`: картинки/GIF через `QImageReader`, видео через ffmpeg (`QProcess`), RGB565 + заголовок + сжатый поток. Кодирование в `QtConcurrent`.

### 4. Оболочка UI [NEW]
- Главное окно, тема Armed (палитра + QSS), боковая навигация, выбор устройства, статус связи (USB / 2.4G и задержка), трей (как в 1.8), «пустой» экран без устройства.
- Страницы создаются лениво при первом открытии, как сейчас.

### 5. Страницы Vial [NEW]
Keymap + вкладки кейкодов, Layout, Macros (запись: Windows/mac — хук, Linux — `pkexec` helper как сейчас), Tap Dance, Combos, Key Overrides, Alt Repeat Key, QMK Settings (из `qmk_settings.json`), Matrix tester, Firmware updater, About.

### 6. Страницы Armed [NEW]
Lighting (эффекты, тема-редактор), Device, Screen (настройки, HUD editor с канвасом/undo/выравниванием, Animation), HUD agent (метрики: Linux `/proc`, `/sys`, hwmon, NVML через `dlopen` вместо `nvidia-smi`; Windows PDH; команды через `QProcess`; `QLockFile`; RUN AT LOGIN).

### 7. Тесты и релиз
- Qt Test: порт нынешних тестов (~1.2 тыс. строк) + golden-тесты HUD + протокол на фейковом устройстве.
- Замеры до/после: время старта, загрузка по USB и 2.4G, кодирование анимации, FPS превью.
- README, docs, релиз 2.0.0; удаление `src/main/python`, fbs, PyInstaller.

## Правки UI/UX по ходу (дешёвые по производительности)

- Никаких модальных «замёрзших» окон: прогресс и ошибки — внутри страницы; некритичные ошибки — всплывающая полоса, а не QMessageBox.
- Единая сетка отступов (8 px), единые размеры шрифтов и контролов, состояния hover / pressed / disabled / focus у всех кнопок.
- Видимый индикатор несохранённых изменений на страницах с SAVE; подтверждение при уходе со страницы с несохранёнными изменениями.
- Порядок фокуса и горячие клавиши на всех страницах; подсказки (tooltips) у иконок.
- HiDPI без размытия (Qt 6 по умолчанию), контраст текста по WCAG AA в теме Armed.
- Превью эффектов и HUD рисуются только когда видны, с ограничением FPS.

## Оценка объёма
~20 тыс. строк Python (+1.2 тыс. тестов) → ожидаемо 25–30 тыс. строк C++. Идём фазами 1→7; после каждой фазы — сборка, проверка на клавиатуре (USB и донгл), коммит.
